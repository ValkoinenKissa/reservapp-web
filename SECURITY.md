# Security Policy

## Supported Versions

Security updates are provided for the latest version available on the default branch.

| Version        | Supported |
| -------------- | --------- |
| Latest         | ✅         |
| Older releases | ❌         |

## Reporting a Vulnerability

If you discover a security vulnerability, please **do not open a public issue**.

Instead, use GitHub's **Private Vulnerability Reporting** feature to submit your report. This allows the issue to be investigated and resolved before any public disclosure.

Please include, where possible:

* A clear description of the vulnerability.
* Steps to reproduce the issue.
* The potential security impact.
* A proof of concept (if available).
* Suggested mitigations or fixes (optional).

## Response Process

After receiving a report, the maintainer will:

1. Acknowledge receipt of the report.
2. Assess the severity and impact.
3. Develop and validate a fix.
4. Publish a security advisory if appropriate.
5. Credit the reporter, unless they prefer to remain anonymous.

Response times may vary depending on the complexity and severity of the issue.

## Security Practices

This repository uses several GitHub security features, including:

* GitHub Security Advisories
* Private Vulnerability Reporting
* Dependabot Alerts
* Automated dependency updates (where applicable)
* Branch protection and pull request reviews

Dependencies are regularly reviewed and updated to reduce exposure to known vulnerabilities.

## Scope

This policy applies only to this repository and its officially maintained code.
